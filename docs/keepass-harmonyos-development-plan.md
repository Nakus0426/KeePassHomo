## 1. 文档用途

本文是 KeePassHomo 唯一的产品范围、设计约束、开发顺序和验收基线。需求、架构、页面、状态与进度均在本文维护，不再拆分独立设计清单。

### 1.1 状态约定

- `[ ]`：未开始、未完成或尚未通过用户手动验收。
- `[x]`：实现、静态检查、构建验证和用户手动验收均完成。
- 部分完成不得标记为完成；受阻事项保持未勾选，并写入“风险与决策记录”。
- 为便于本机调试而临时关闭的安全能力仍按已实现记录，但必须在第 18 章登记，并在阶段 7 发布收敛前恢复。

### 1.2 优先级

- `[P0]`：首版必须完成，缺失会导致核心流程、安全边界或产品信息架构不完整。
- `[P1]`：首版只做能力验证，验证通过后另行决定是否实现。
- `[P2]`：后续版本候选，不进入 P0 主流程。

## 2. 产品边界

### 2.1 产品原则

- [ ] `[P0]` 用户无需注册、登录产品账号或购买订阅即可使用。
- [ ] `[P0]` KDBX 文件是唯一数据真源，不建立不可导出的私有密码库格式。
- [ ] `[P0]` 默认离线可用；仅 WebDAV 同步和用户主动开启的泄露检测需要联网。
- [ ] `[P0]` 高风险操作必须明确反馈，不允许静默覆盖、上传、删除或降低安全级别。
- [ ] `[P0]` 敏感值默认遮挡；截图、最近任务、剪贴板、日志、路由和后台切换均按安全优先处理。
- [ ] `[P0]` Phone 与 Tablet 共享相同信息架构；Tablet 只利用额外空间提升效率，不增加独有功能。
- [ ] `[P0]` 可参考成熟密码管理器的功能完整性和操作效率，不复制其品牌、配色或页面构图。

### 2.2 明确不做

- [ ] `[P1]` 系统级自动填充只做能力验证，不承诺 P0 接管系统密码保险箱。
- [ ] `[P2]` Passkey 保存与填充。
- [ ] `[P2]` Dropbox、OneDrive、Google Drive、SFTP 等额外同步源。
- [ ] `[P2]` KeePass 1.x `.kdb` 文件导入。
- [ ] `[P2]` 家庭共享、团队空间、成员权限和审计后台。
- [ ] `[P2]` 产品账号、订阅和云端托管密码库。

## 3. 架构与执行规则

### 3.1 开发顺序

```text
技术闸门与本地最小闭环（已完成）
  -> 架构与全局能力底座（已完成）
  -> 保险库模块（进行中）
  -> 安全中心模块
  -> 生成器模块
  -> 设置模块（含 WebDAV 与同步）
  -> Tablet、无障碍、状态覆盖与发布收敛
  -> P1 自动填充能力验证
```

执行约束：

- 架构和跨模块能力必须先稳定，再开发依赖它们的页面。
- 四个底部导航模块严格按“保险库 → 安全中心 → 生成器 → 设置”顺序完成；前一模块未通过人工验收，不进入下一模块。
- 同一模块按“领域模型 → ViewModel → 页面 → 异常状态 → 构建 → 人工验收”完成纵向闭环。
- 不为了铺页面同时并行开发多个主模块，不创建无业务行为的视觉占位功能。
- WebDAV 页面归属设置模块；其接口、版本比较和冲突状态机在全局底座阶段先定义。

### 3.2 分层与依赖方向

```text
View（ArkUI）
  -> ViewModel（状态管理 V2）
  -> Domain Service（业务规则）
  -> Repository / Engine（文件、KDBX、网络、系统能力）
```

- View 只负责渲染和用户事件，不直接调用文件、密码学或网络接口。
- ViewModel 管理页面状态和业务编排，不持有不可控的明文敏感副本。
- Domain Service 不依赖 ArkUI 组件。
- Repository 和 Engine 只在系统边界校验外部输入与错误。
- Ability 只处理生命周期、窗口初始化和全局隐私遮罩协调。
- 公共能力放入 `common`；单模块 View、ViewModel 和状态留在所属业务模块。

### 3.3 状态管理

- 新页面、组件和 ViewModel 优先使用状态管理 V2：`@ComponentV2`、`@ObservedV2`、`@Trace`、`@Local`、`@Param`、`@Event`、
  `@Monitor` 和 `@Computed`。
- 应用级共享状态优先使用 `AppStorageV2`；确需持久化的非敏感设置使用 `PersistenceV2`。
- 敏感值、解锁会话和临时候选不得因使用 `PersistenceV2` 而落盘。
- 父向子传递使用 `@Param`，子向父发出意图使用 `@Event`，避免隐式双向修改。
- 复杂领域对象使用 `@ObservedV2 + @Trace` 做属性级观测，避免页面通过复制数组或对象强制刷新。
- 只有确认 API 26 下 V2 无法满足具体场景，并记录官方依据、限制和影响后，才允许局部使用 V1。
- 现有 V1 代码按页面边界迁移，不在一次功能开发中同时保留两套状态真源。

### 3.4 路由与模块边界

- [x] 使用 `Navigation + NavPathStack + NavDestination` 建立真实页面栈。
- [x] 采用系统路由表：`module.json5` 配置 `routerMap`，`route_map.json` 注册全部页面，各页面导出 `@Builder` 构建函数，跳转经 `pushPathByName` 由系统路由表解析。
- [x] 路由操作统一收敛到 `AppRouter` 单例（`push`/`pop`/`resetTo`/`backToPreviousRoute`/`topParam`），`currentRoute` 由 `uiObserver.on('navDestinationUpdate')` 自动同步，页面不再手动回写。
- [x] 集中维护认证、保险库、条目、安全中心、生成器和设置路由名称。
- [x] 路由参数不传递密码、凭据、TOTP 密钥、完整条目或其他敏感数据；非敏感定位信息（如条目 UUID）通过路由 `param` 传递，页面在 `aboutToAppear` 读取。
- [x] 页面表单与编辑状态归属页面域 ViewModel（随 NavDestination 入栈创建、出栈销毁，不跨导航残留）；浏览状态等模块级状态归属独立域 ViewModel；会话与生命周期状态归属 `AppViewModel`。
- [x] Phone 使用单栈导航和四模块悬浮胶囊底栏。
- [ ] 每个主模块拥有独立页面入口、ViewModel 和内部路由，不再集中于单个巨型页面组件。
- [x] 页面文件按一页一文件组织；仅当前页面使用的组件可与页面同文件，跨页面复用的组件再抽取为独立文件，禁止多个页面集中在同一个 `.ets` 文件。
- [ ] 全局锁定后清空业务返回栈，统一进入安全遮罩与解锁流程。
- [ ] Tablet 复用同一路由名称和领域状态，只替换页面容器与布局策略。

### 3.5 写入、同步与安全顺序

1. 用户保存条目后，在本机安全临时文件中生成完整 KDBX。
2. 新文件可重新打开并校验后，安全替换当前本地文件。
3. 本地保存成功立即反馈；WebDAV 上传是后续同步步骤。
4. 上传前比较远端版本标识、修改时间和内容摘要。
5. 远端未变化才上传；本地与远端均变化时进入冲突。
6. 冲突解决前不覆盖任何版本；替换前备份将被替换的版本。

## 4. 全局信息架构与设计系统

### 4.1 主导航

| 入口   | Phone     | Tablet    | 默认落点      |
|------|-----------|-----------|-----------|
| 保险库  | 底部悬浮胶囊    | 左侧悬浮导航栏   | 最近分组或全部条目 |
| 安全中心 | 底部悬浮胶囊    | 左侧悬浮导航栏   | 安全概览      |
| 生成器  | 底部悬浮胶囊    | 左侧悬浮导航栏   | 随机密码      |
| 设置   | 底部悬浮胶囊    | 左侧悬浮导航栏   | 设置首页      |
| 搜索   | 保险库顶部搜索胶囊 | 条目列表顶部搜索栏 | 全库搜索      |
| 锁定   | 顶部锁定按钮    | 侧栏底部锁定控件  | 解锁页       |

- 引导、数据源选择和解锁阶段隐藏主导航。
- 切换底部模块必须执行真实路由跳转，不以条件分支替换主页面组件；当前实现仍是 `HdsTabs` 条件换页，偏差与待决策事项记入第 18
  章。
- 主模块切换保留必要的非敏感界面状态；锁定时全部清除。

### 4.2 页面容器规则

| 容器   | 适用内容                   | 典型场景                                  |
|------|------------------------|---------------------------------------|
| 独立页面 | 高频主任务、长列表、长表单、稳定返回节点   | 保险库、安全中心、生成器、同步中心、设置、搜索、分组管理          |
| 半模态  | 从当前上下文发起、完成后返回原位置的中等任务 | 条目详情与编辑、模板选择、生物认证、旧库升级、TOTP、移动、冲突、再认证 |
| 临时浮层 | 少量选项、筛选、排序和更多操作        | 条目排序、筛选、标签、同步状态菜单                     |
| 确认弹窗 | 不可逆操作和阻断错误             | 永久删除、清空回收站、放弃修改、证书错误                  |

- 同一时刻只显示一个半模态；简单二级选项使用面板内菜单。例外：“模板选择”这类选择或跳转场景允许在新半模态上再开一个半模态，其余场景仍只允许一个。
- 半模态关闭后恢复滚动位置、筛选、选中项和键盘焦点。
- 未保存内容、高风险确认或进行中任务不得因点击遮罩直接丢失。
- 无法继续当前任务的错误才使用完整错误页；可原地恢复的错误使用半模态或行内反馈。

### 4.3 沉浸光感

| 场景               | 材质档位          | 约束                |
|------------------|---------------|-------------------|
| 顶部标题栏、搜索栏        | `ULTRA_THIN`  | 内容延伸至其下，滚动时平滑增加模糊 |
| 底部导航、操作坞、MiniBar | `THIN`        | 与安全区保持悬浮间距        |
| 临时菜单、筛选面板        | `THICK`       | 关闭后不保留光效          |
| 半模态、操作面板、阻断弹层    | `ULTRA_THICK` | 稳定对比度和明确遮罩层级      |
| 列表、表单、密码字段、风险正文  | 无常驻强材质        | 使用稳定实色内容面         |

- [ ] `[P0]` 默认使用系统 `ADAPTIVE` 材质级别，尊重系统强度和设备性能。
- [ ] `[P0]` 除明确隐藏标题栏的页面外，标题栏默认使用 HDS 内置标题栏、系统 `ADAPTIVE` 沉浸光感材质和
  `IMMERSIVE_GRADIENT_BLUR` 动态渐变模糊；绑定实际滚动容器，并确保默认位置的内容避让标题栏和底部导航区域，滚动后才允许内容进入标题栏背后参与模糊效果。
- [ ] `[P0]` 同屏常驻悬浮层不超过顶部栏、底部栏和一个上下文层。
- [ ] `[P0]` 不使用玻璃卡片嵌套、营销式渐变、装饰色球或无功能光斑。
- [ ] `[P0]` 按压、滚动和材质变化遵循减少动态效果设置，不使用夸张弹跳。
- [ ] `[P0]` 高级材质不可用、节能、低性能或减少透明度时，只降低材质，不改变布局与功能。

### 4.4 色彩、尺寸与无障碍

- [x] 颜色、间距、圆角、字号、标准控件和系统组件尺寸优先复用 API 26 SDK `sysResource.js` 中语义一致的
  `sys.color.*` 与 `sys.float.*`；新增应用 Token 前必须查官方 API 与 SDK 定义，禁止仅因数值相同进行替换。
- [x] 所有 UI 颜色默认使用 `sys.color.*`，品牌色使用 `sys.color.brand`，成功、提醒、错误状态分别使用
  `sys.color.confirm`、`sys.color.alert`、`sys.color.warning`；除非用户明确指定颜色，否则不新增自定义应用颜色。
- [x] 仅在配置 schema 无法引用系统颜色（例如启动窗口配置）或用户明确指定颜色时维护应用颜色资源；业务布局约束等产品专属尺寸
  Token 可保留，并删除已由系统资源替代或无引用的重复 Token。
- [x] 浅色与深色通过 `resources/base`、`resources/dark` 同名资源覆盖。
- [x] 品牌色和业务状态色跟随 HarmonyOS 系统颜色角色及深浅色策略。
- [x] 字符串资源按页面/功能拆分为多个 `string_<scope>.json`；跨页面文案集中到 `string_common.json`，保持资源 key 全局唯一。
- [ ] 背景使用不透明的系统背景 Token；成功、提醒、警告使用独立语义色。
- [ ] 风险同时使用 Symbol、文字和严重度，不只依赖颜色。
- [ ] 常见操作使用 HarmonyOS 系统 Symbol；图标按钮提供无障碍名称和触摸提示。
- [ ] 固定导航、图标按钮、计数器和 TOTP 倒计时使用稳定尺寸。
- [ ] 支持系统字体缩放、高对比度、减少透明度和减少动态效果。
- [ ] 长库名、网址、文件名和错误文本允许换行或省略，并提供完整查看入口。

## 6. 阶段 2：架构与全局能力底座

目标：清除后续四模块都会依赖的架构债务，建立唯一状态源、模块边界和全局安全行为。

### 6.1 状态与页面拆分

- [x] 将现有主页面从状态管理 V1 迁移为 `@ComponentV2` 页面和 `@ObservedV2` ViewModel。
- [x] 建立应用会话、路由、保险库和生成器的 V2 状态边界；安全中心和设置在产生首个业务状态时建立边界，不创建空 ViewModel。
- [x] 使用 `AppStorageV2` 共享应用会话、锁定状态和当前底栏模块等非敏感全局状态。
- [x] 明确 `PersistenceV2` 只接收非敏感用户设置；当前尚无用户设置，因此不提前创建持久化状态。
- [x] 将巨型入口页面拆为 AppShell、各模块 Page、ViewModel 和可复用业务组件。
- [x] 每个状态只有一个写入所有者；View 通过意图方法或 `@Event` 请求变更，不直接修改其他模块状态。
