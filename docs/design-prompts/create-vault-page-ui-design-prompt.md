## 提示词正文

你是一位精通 HarmonyOS 原生设计语言（HDS）与「沉浸光感」风格的高级 UI/UX 设计师。请为一款本地优先的密码管理器（KeePass 兼容客户端）重新设计「创建新保险库」页面，产出高保真设计稿。

这是一次开放式重设计：不必沿用常见的"表单卡片堆叠"套路，请发挥创造力重新组织信息架构——可以探索但不限于：分步向导（Stepper）、渐进披露表单、单屏聚焦流、拟物隐喻（例如"铸造一把钥匙/开启一座保险库"的仪式感叙事）等。无论何种布局，必须让首次使用的普通用户在无提示的情况下理解每一步在做什么、为什么需要主密码。

### 画布与范围

- 手机竖屏，画布 390 × 844（vp 单位，1vp ≈ 1px@3x 输出时按 1170 × 2532）。
- 仅浅色模式，仅 Phone 单栏布局；页面可以滚动，也可以设计为多步流程。
- 共 8 张状态稿，共享同一设计语言与布局骨架（若为分步设计，状态差异体现在步骤进度与控件状态上）。

### 必须承载的功能要素（缺一不可，形态由你定义）

1. 页面身份：让用户知道当前在"创建一个全新的、由主密码保护的本地 KDBX 保险库"，并强调数据只存在本机。
2. 保险库名称：文本输入，占位「个人保险库」。
3. 保存位置：选择器入口，初始文案「选择保存位置」，选定后显示文件名（如「个人保险库.kdbx」）。
4. 主密码 + 确认主密码：两个密码输入，内容一律遮罩圆点，禁止任何状态稿出现明文密码。
5. 密码强度反馈：文案三档「强度：较弱 / 强度：一般 / 强度：较强」。
6. 生成主密码建议：一个入口让用户改用应用生成的强主密码；使用生成密码后必须出现确认勾选「我已妥善保存生成的主密码」（未勾选不得放行）。
7. 密钥文件（可选）：选择入口，初始「选择密钥文件（可选）」，选定后显示文件名（如「secret.keyx」）；必须始终可见警示文案「遗失密钥文件将无法打开保险库」。
8. 创建摘要：至少体现「格式：KDBX 4.x」和凭据构成「凭据：仅主密码」或「凭据：主密码 + 密钥文件」，随用户选择实时联动。
9. 主操作「创建新保险库」与进行中文案「正在创建」。
10. 行内状态反馈区：校验失败与创建失败的错误文案在此展示，不用弹窗打断。

### 8 张状态稿及差异

- 状态 1「初始」：全部为空态/占位，用户第一次看到的样子；摘要为「凭据：仅主密码」。
- 状态 2「密码强度反馈」：密码已输入（遮罩点），强度行展示三档——请并排给出三个局部小样：「强度：较弱」「强度：一般」「强度：较强」，可用语义图标或克制的色彩点缀区分档位。
- 状态 3「密码不匹配」：确认密码非空且与主密码不一致，出现警示文案「两次输入的主密码不一致」。
- 状态 4「已生成主密码建议」：两个密码框填入遮罩点，出现未勾选的确认项「我已妥善保存生成的主密码」。
- 状态 5「已选保存位置与密钥文件」：位置显示「个人保险库.kdbx」，密钥文件显示「secret.keyx」，摘要联动为「凭据：主密码 + 密钥文件」。
- 状态 6「表单校验失败」：状态区显示「请填写库名、选择保存位置并输入主密码」。
- 状态 7「创建中」：主操作变为进行中「正在创建」并禁用（含环形 loading），页面呈非交互感。
- 状态 8「创建失败」：状态区显示「创建保险库失败：存储空间不足」，操作恢复可用，用户已填内容保留。

### 全局风格规范（HarmonyOS 沉浸光感）

- 系统色彩体系：页面背景浅灰 `#F1F3F5`、内容面纯白 `#FFFFFF`、品牌蓝 `#0A59F7`、主文字 rgba(0,0,0,0.95)、次级文字 rgba(0,0,0,0.60)、警示橙 `#D7500B`、错误红 `#E84026`。hex 为浅色参考近似值，语义以 HarmonyOS 系统资源为准。
- 沉浸光感：顶部区域使用 ULTRA_THIN 档半透明模糊材质，内容可滚动延伸至其下并有柔和渐变模糊；若设计为分步流程，步骤指示区可使用 THICK 档。承载输入、密码字段与风险正文的区域保持稳定实色内容面，禁止玻璃卡片嵌套。
- 尺寸节奏：控件高度 48vp、基础圆角 16vp、间距节奏 12/16/20/24vp、页面左右页边距 24vp；正文 16fp、辅助说明 13fp、页头级标题 22-26fp。
- 风格克制：留白充足、层级清晰、动效暗示轻微；禁止营销式渐变背景、装饰光斑、彩色气球图形。
- 触达安全主题时可借助 HarmonyOS Symbol 式线性图标（盾牌、钥匙、锁），保持单一品牌色点缀。

### 禁止项

- 不做深色模式、不做平板布局、不做英文界面。
- 不出现账号、注册、订阅、云托管等与本地优先冲突的概念。
- 不显示明文密码；高风险警示（密钥文件遗失）不得弱化为可忽略的样式。
- 不新增功能要素清单之外的按钮、入口或业务文案。

### 交付要求

- 8 张独立设计稿，统一 390 × 844、浅色模式，每张标注状态名称。
- 界面文案使用上面给出的中文文案原文，不得改写；布局性、引导性文案（如步骤标题、说明段）可自行撰写，但需符合本地优先与安全优先的语气。
- 附一页简短设计说明：信息架构思路、为何该布局有利于首次用户理解主密码的重要性。

## 状态与代码的对应关系（给开发对照，不必粘贴给设计工具）

| 设计状态 | 代码依据 |
|-------|--------|
| 1 初始 | 页面默认态，`vaultName/createFileName/masterPassword` 为空 |
| 2 密码强度反馈 | `passwordStrength()`：长度 ≥16 较强、≥10 一般、否则较弱 |
| 3 密码不匹配 | `confirmPassword` 非空且与 `masterPassword` 不等，`app.string.password_mismatch` |
| 4 已生成密码建议 | `generatedMasterPassword` 为 true 时出现 `password_saved_ack` 勾选行 |
| 5 已选位置与密钥 | `createFileName` 与 `currentKeyFileName()` 非空时按钮文案与摘要联动 |
| 6 表单校验失败 | `createVault()` 前置校验 `setStatus('请填写库名、选择保存位置并输入主密码')` |
| 7 创建中 | `busy` 为 true，按钮文案 `app.string.creating` 且禁用 |
| 8 创建失败 | `reportBoundaryError('创建保险库失败', error)` 写入 `StatusText` |
